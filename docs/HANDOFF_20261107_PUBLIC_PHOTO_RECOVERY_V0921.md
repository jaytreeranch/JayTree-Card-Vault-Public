## Problem and behavior
The public gallery's existing lazy card pictures and full-size detail images had no error handling. When a CDN/front JPG is missing, slow/offline or fails, the card image could display broken/blank artwork even as card details and public records remain available. The previous code assigned img.src before setting lazy loading/async hints. A separate LAN thumbnail request (Coordination/Requests/20261107_1934_PUBLIC_TO_LAN_APPROVED_CARD_THUMBNAILS_V1_REQUEST.md) is still PENDING and is NOT approval to generate/rewrite any private or public images.

v0.9.21 applies lazy/async/low-priority hints and installs the error handler BEFORE source assignment for gallery JPGs. A failed image element is removed and replaced by a readable Photo temporarily unavailable placeholder inside the existing clickable card; the card button's accessible label additionally announces photo temporarily unavailable (unnamed players are labeled Unnamed). Existing review caution, status, offer tags, metadata, owner estimates and card deep links remain. Gallery Low-data option still renders no img tags and no gallery-photo network until opted in. The detail view loads the same allowlisted public front JPG eagerly on explicit open, and keeps all nonphoto details readable if it fails. Its role=status text announces the failure and a minimum 44px-tall Retry card photo control enables at most TWO user-click requests per open detail, adding a transient ?retry=<time>-<attempt> query to that same safe public JPG to avoid a previously cached error. After the second failure, retry hides with a clear try-later message. No automatic polling, background retry, new API or storage, no guessing missing card identities or replacing public source paths. A renewed detail open is a new user gesture/session.
